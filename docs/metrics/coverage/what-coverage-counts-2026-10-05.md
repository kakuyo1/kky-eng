# 覆盖率数的是代码行数吗

不是。两条线数的是**两种不同的东西**，而且都只回答一件事：哪些东西被测试跑过，不回答跑过的结果对不对。
一行被执行过，不等于它产生的结果被断言过。下面两行数字**不可比，也不许平均**。

## C++ 那条线：机器码的行

工具是 `OpenCppCoverage`，它读 `build-ninja` 里 Debug 二进制的 PDB，在运行时插桩。数的是 `src/` 下被
测试目标链进去的源文件里**编译器生成了可执行指令的行**，某一行被算作 “执行过”，当且仅当它产生的指令
里至少有一条跑到了。

所以这条线的分母是编译器给的，不是人给的：声明、宏、注释、被优化掉的代码都不在其中。一个只被
`lens.exe` 引用的文件（`main.cpp`、`qt_log.cpp`）根本不会进测试二进制的链接行，因此**不报出来**——
那不叫 0%，叫 “没有可归因的行”。`profile.cpp` 读数低也不是缺口：`LENS_ENABLE_PROFILE` 在这棵树上关着，
测量点编译成了空。口径与例外见 [`TEST.md` §4](../../../TEST.md)。

## QML 那条线：被求值的表达式位置

Qt 没有 QML 的行覆盖率工具，这是结构问题不是遗漏：`.qml` 主要在声明对象，而声明一个对象不是一行
“执行”。会执行的是里面的 JavaScript——属性绑定、signal handler、函数——唯一报告这些的是 QML
profiler：每求值一次就记一条带文件与行号的事件。

所以这条线的单位是**位置**，不是行，而且一个位置只记 “求值过没有”，不记 “两条分支都走到没有”。分母
来自 `tree-sitter-qmljs` 建的解析树（`scripts/quality/qml-coverage.js`）：模块里每个非字面量的 `ui_property`
与 `ui_binding`，加上每个 `function_declaration`；字面量的绑定两侧都不算——编译器把它折进对象的构造，
引擎从不求值，算进分母就是一笔永远扣不掉的分。

无头跑不渲染，所以 `qsTr()` 标签绑定永远不求值，未执行的位置里约四分之一是这一条造成的，那不是缺口。

## 两条线为什么不能放一起

分子、分母、工具、单位四样都不同：一个数机器码的行，一个数表达式的位置。相加或平均得到的数没有
对应任何东西。**读完哪条线，看数字来自哪个目标**：`.exe` 是 gtest 与 QTest 目标，`.qml` 是 QML 模块。

两条线都**以构建树为准**：C++ 走 PDB，QML 编进二进制，改了源码没重新构建（重新链接），量到的是旧
版本。本轮就踩过一次——一个文件在重建前后读 19% 与 52%。

## 数字之外

**没有阈值**（`.github/workflows/ci.yml` 的注释写了理由）：同一棵不改的树，两条线都会自己小幅摆动，
阈值会卡在天气上。要做趋势就按日期存报告比，本目录就是那么存的。

## 复现

```bash
sh scripts/quality/coverage.sh      # C++，写 test/records/coverage/，需要 OpenCppCoverage 与新的 build-ninja
sh scripts/quality/qml-coverage.sh  # QML，写 test/records/qmlcov/，需要 node_modules 与 Qt 的 qmlprofiler
```

两条都读**已经构建好**的树，都不新建树、不加编译标志。跑之前先确认 `build-ninja` 比源码新。
