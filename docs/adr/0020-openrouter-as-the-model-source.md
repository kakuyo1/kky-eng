# 0020 模型列表取自一个共用的源

- **状态**：accepted
- **背景**：每家服务商各带一份 `modelList`（0018），代价有三层。一，每家一次带认证的 GET，读者必须先有
  key 才拿得到任何列表——从没填过 key 的人看到的永远是目录种子。二，xAI 的接口在官方文档里根本没有，
  那一家的 “列表” 是照别家的约定猜出来的。三，转售服务（OpenRouter）一家的回答就是几百条这个应用根本
  用不上的 id，而各家的响应结构又各不相同，Google 连路径和 envelope 都不是 OpenAI 兼容的那一套。
- **决定**：模型列表改为**一条**不带认证、不带查询的 GET，问 `modelSource` 声明的那个共用的源；
  各家条目上的 `openRouterPrefix`（OpenRouter id `vendor/slug` 的 vendor 部分）把回答切成各自那一份，
  取到字段前去掉前缀，空前缀表示整份目录、id 保持原样（OpenRouter 自己，它的接口收的就是 `vendor/slug`），
  没有前缀的服务商不参与切分。带 `:` 的 id（OpenRouter 自己的路由与计价模式）与 `output_modalities`
  不是恰好只有 `text` 的条目在读进来时就丢掉。回答按原有键写进各家的 `MODELS`，触发时机一字未改：
  启动、换服务商、改 API key、改服务地址、展开服务商下拉（0017）。**取到的列表不再改写当前模型**：
  0017 那条 “当前模型不在它报的列表里就换成列表第一条” 在取列表这条路上作废，只保留在换服务商上——
  见下。
- **后果**：
  - 这是整个行业的清单，不是当前那家服务的货架，所以**服务不提供的名字仍然选得到**，也就仍然会得到 0017
    说的那个报 “格式错误” 而不提模型的 400。缓解是两条：字段本身可输入，且换服务商时那一步仍在修剪明显
    属于别家的模型。证据在下面第三段。
  - 每次启动多一次对第三方的出站请求，不带 key、不带读者内容（0012 仍然成立）；没有 key 的读者同样会发，
    这是接受的代价而不是设置项。
  - 价目不动：`pricing.json` 仍是手工核对过的表，源自己那份 `pricing` 不并进来，所以不在表内的模型照样
    记 0 元。
  - `:free` 这类 id 与能出图 / 出音频的对话模型只能手打进字段——它们被滤掉是有意的。
  - 出厂默认的 `deepseek-flash` 是 DeepSeek 在 `catalog.json` 与 `pricing.json` 里的种子，而它**不在**
    OpenRouter 的 `deepseek` 段里。0017 的前提是 “服务自己的回答是它有什么模型的唯一权威”，而一份全行业
    的清单不是那个权威：照旧改写会让首次启动后的每位 DeepSeek 读者被静默换到该段第一条（2026-10-09 为
    `deepseek-v4.1-flash`），那个名字不在价目表里，默认配置的费用行会直接读成 “No listed price”。
