# 0017 模型跟随服务商，列表取自服务商自己

- **状态**：accepted
- **背景**：0015 定的是 “换服务商只改地址，模型手填、不跟随”。代价在实机上现形：读者从 OpenAI 换回
  DeepSeek 后，模型仍是 `gpt-4.1-mini`、地址是 `api.deepseek.com`，此后每一次取词都是 HTTP 400，而提示
  只说 “请求被拒绝为格式错误”，一个字不提模型。读者改的是服务，不是模型。
- **决定**：
  - **选服务商时模型跟着走**：`data/llm/catalog.json` 每个服务商带一份 `models`（最常见的在前），换服务商
    即把模型填成该列表的第一条；**当前模型已经在这个服务商的列表里就原样保留**，来回切换不会丢掉一个
    仍然有效的选择。
  - **列表以服务商自己为准**：按目录中该服务商的官方模型列表接口查询，随每次换服务商与每次启动各问一次，答案
    按服务商存进设置文档的 `MODELS`，覆盖目录里那份。种子只为从未连上的机器存在——这也是只有 DeepSeek 与
    OpenAI 有种子、其余留空的原因：没有核实过的模型名写进去，等于把 400 换个地方埋。
  - **设置页的模型是一个可输入的下拉**（2026-10-07 同日修订，原为 “手填输入框改为列表下拉”）：正文直接改
    模型名，只有右端 chevron 开列表。改成纯下拉是错的——自定义端点没有列表，私有部署与服务商从没报过的名字
    进不来，而 “服务商报了列表就把输入框收掉” 会让这个字段在列表到达前后换形状，读者读成 “换服务商没生效”。
    一个控件、两种用法，形态不变。
  - **列表只留能发对话请求的模型**：`/models` 报的是整张货架，嵌入、语音、图像、视频混在其中；OpenRouter
    这类转售服务的列表动辄数百条，全画出来又慢又没法找。有 `architecture.output_modalities` 的按它判，没有
    的按 id 判。
  - **列表不再挂在 `settings()` 这个 map 上**：它是设置页读的最长的一份数据（数百条 × 每条一个 map），而那个
    map 每次变动都被页面几十个绑定重建。改为 `Controller.models` 单独一条属性、单独一条通知。
  - **取列表的时机**：换服务商、启动、改 API key、改服务地址各一次——能否问出列表取决于这三样，它们一变就重
    问（模型必须跟着服务商走，不能等到读者去点）。列表高封顶 290 px，超出在列表内滚动。
  - **没有列表就把 chevron 灰化**：服务商一次都没报出模型（键不对、端点不报、网络不通）时，字段右上角的
    chevron 按 0.45 透明度灰掉、不吃点击。第一版让它点了去问服务商，结果实机上换到 Zhipu（键是 DeepSeek 的）
    每次点击都发一个 401、界面毫无变化，读者读到的是 “这个控件坏了”。一个看起来能点、点了没反应的按钮，比一个
    明说自己没东西可开的按钮更糟。灰化而不隐藏：字段的形态是读者判断 “换服务商生效了没有” 的依据（见上）。
  - 取列表失败留着已有那份，不弹卡片。取到了则以服务商为准：**当前模型不在它报的列表里就换成列表第一条**——
    那正是会答 400 的那个名字，服务商自己的回答是 “我有哪些模型” 的唯一权威。只在这一种情形下改，且只在
    消费者仍是同一个服务商时改（请求在飞行中时读者可能已经换走了）。
- **后果**：
  - `MODEL` 不再是读者唯一的所有权：换服务商会重写它。“每个服务商各记一个模型” 的入口在
    `ExplanationDuty::setProvider`，现在刻意没做。
  - 每次启动多一个 GET；没有 API key 时跳过。
  - 0015 的 “服务商只改地址” 连同 “模型手填、不预填” 一并由本文件取代，其余（目录不带模型清单、地址以官方
    文档为准）不再成立的部分见上。
