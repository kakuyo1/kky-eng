# 0016 截图取词的触发键与蒙版

- **状态**：accepted
- **背景**：截图取词在 2026-10-06 从设置里下架，等一个比 “设置里点一下” 更合适的触发面。它要能在
  任意程序上按下去，所以必须是全局热键，而不是窗口级快捷键——而窗口级之外，这个程序里唯一会泵消息的
  地方只有鼠标钩子那条自己的线程（`docs/adr/0001`）。
- **决定**：
  - 全局热键注册在**主线程**上，用 `QAbstractNativeEventFilter` 收 `WM_HOTKEY`，不新起线程、也不并进
    鼠标钩子那条。依据是 Qt 自己的实现而非猜测：`QEventDispatcherWin32::processEvents` 用
    `PeekMessage(&msg, 0, 0, 0, PM_REMOVE)` 取**整个队列**（含 `hwnd == 0` 的线程消息），再把每条交给
    `filterNativeEvent("windows_generic_MSG")`，所以主线程注册的 `WM_HOTKEY` 一定送得到。
    鼠标钩子另起线程是因为 `WH_MOUSE_LL` 的回调有 300 ms 预算、主线程给不起；热键没有这个约束，
    一条 posted 消息在队列里等一会儿是延迟，不是超时。
  - 触发后拉起**每屏一张**全屏压暗蒙版，拖拽框选一块矩形，交回 `CaptureDuty::captureRegion`；
    取到的文本走既有的选区通道（本地分类 → 选区动作条），不另开一条 “取完即解释” 的捷径。
  - 抓屏前蒙版**先隐藏并等过一帧**（`Mask.qml` 的 `settleMs`）：`QScreen::grabWindow` 读的是屏幕 DC，
    蒙版自己也在画面里，不隐藏就会把压暗拍进 OCR。
  - 起不来（开关未开 / 运行时不可用 / 正在识别 / 预算暂停）时弹通知说明原因，不静默。
- **后果**：
  - 热键组合与注册失败都必须能被读者看见：设置页在组合被别的程序占用、或不合规（不含 Ctrl / Alt）时
    明说。一颗按不响的键最像 “程序坏了”。
  - 蒙版是全程序唯一接受焦点的表面，会短暂抢走前台应用；取词之后不还原焦点（读者本来就在往别处看）。
  - 被排除的选项：并进鼠标钩子的线程（要给它加一份热键状态，类名也就不再诚实）；为跨屏拖拽做矩形
    跨屏拼接（抓屏只接受落在单块屏幕内的矩形，跨屏拖拽夹取到起始那块屏就够用）。
