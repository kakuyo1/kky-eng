# 0022 更新卡片下载安装包，校验后由读者启动

- **状态**：accepted，取代阶段三计划里的 “只打开发布页，不下载、不安装”
- **背景**：只给一个发布页链接，读者要自己找到 Windows 安装包、下载、运行，中途任何一步失败都没有反馈。
  安装包约 48 MB，国内直连 GitHub 不通，读者通常要开代理；没有下载入口，就等于把这段路全部留给读者。
  另一方面，安装包未签名，运行中替换可执行文件风险高，所以静默安装仍然不做。
- **决定**：更新卡片提供**下载**，读者按下才开始。流程是：取该版本的 `SHA256SUMS`，再取安装包写到
  `%LOCALAPPDATA%\Lens\updates` 下的 `.part` 文件，SHA256 与校验列表一致后才改名；运行前再校验一次；
  运行时不带任何参数，由读者按 “安装” 触发，不静默。没有 `SHA256SUMS` 的发布不可下载，卡片只保留 “查看” 与 “跳过”。
  重定向只按白名单跟随（GitHub 的下载路径与两个资源域名，最多五跳），大小、停滞与连接各有上限。
- **后果**：
  - 校验只证明传输完整，**不证明发布者身份**。真正的作者验证需要代码签名，签名方案待定；界面与文档都不得声称已验证作者。
  - 每个发布都要附 `SHA256SUMS`，这是发布流程的新增步骤，写入 `TODO.md`。
  - 国内无代理时下载会失败，程序只在一个字节都没有收到时提示代理；传输中途停滞只报普通失败。
  - 下载不显示进度数字，只显示 “下载中”。
  - 被排除的方案：静默安装（未签名，运行中替换风险高）；只开发布页（读者负担过重，国内尤甚）；
    等代码签名后再做（签名证书尚无，会把功能无限期推后）。
